# 找不同完整小游戏设计规格

日期：2026-05-10

## 目标

将 `games/difference-hunt` 完善为一个完整的移动端竖屏找不同小游戏。玩法只保留找不同，不接入 `normalGame`、`addGame` 等其它玩法类型。实现应遵守根目录 `AGENT.md` / `AGENT_CN.md` 和 `games/difference-hunt/AGENT.md` / `AGENT_CN.md`：短局、轻量、核心流程稳定、简体中文文案、清晰页面、主动触发的视频广告入口、顺序关卡解锁和兼容旧存档。

## 范围

本次工作范围限定在 `games/difference-hunt` 当前游戏项目内：

- 使用 `games/difference-hunt/levels/assets/findGame` 作为关卡和图片资源来源。
- 当前已接入前 5 关，应补齐 `findLevel6`、`findLevel7`，形成 7 关找不同内容。
- 保留现有 Vite + Canvas 架构和 mini-pack 入口，不迁移到 Cocos，也不扩展新玩法。
- 重做或打磨首页、游戏页、选关页、设置页、胜利弹窗、失败弹窗的视觉层级，使其更像正式小游戏。
- 保留浏览器预览能力，同时保证 mini-pack 运行时不依赖普通网页环境。

不做范围：

- 不接入其它 Cocos 玩法目录。
- 不新增长线系统、复杂任务系统或内容型页面。
- 不把按钮文案、数值或奖励说明画死在图片里。

## 页面与流程

首页：

- 第一屏展示游戏名、当前进度、当前关卡图片预览、金币、提示、每日奖励状态。
- 主入口为“开始游戏”，辅助入口为“选择关卡”“领取每日奖励”“设置”。
- 文案全部使用规范简体中文。

游戏页：

- 基于 750 x 1334 设计尺寸绘制，双图找不同区域作为视觉中心。
- 顶部展示关卡名、倒计时、剩余差异数量和基础导航。
- 底部展示已找到差异槽位、提示入口和广告加时入口。
- 点击差异后同时标记上下两张图；错误点击给出轻量反馈，不阻塞流程。

选关页：

- 展示 7 个关卡，包含已通关、已解锁、未解锁状态。
- 默认从第 1 关开始，通关后解锁下一关。
- 已解锁关卡可直接进入，未解锁关卡可主动点击观看视频广告解锁。

设置页：

- 提供音效开关和进度概览。
- 关闭声音后不播放音效。

结算与失败：

- 胜利弹窗显示本关奖励、广告翻倍、继续下一关、选关、首页。
- 失败弹窗显示倒计时结束原因、重试、选关和广告加 30 秒。
- 弹窗必须有半透明遮罩，打开期间阻止点击穿透。

## 资源接入

从 `levels/assets/findGame/findLevelN/texture` 复制每关图片到 `game/public-pack/assets/find/level-00N`。每关使用 `pictureNN_11` 作为背景图，其余 `pictureNN_01` 到 `pictureNN_10` 作为差异标记图。

从 `levels/assets/findGame/findLevelN/prefab/Level.prefab` 提取每个差异节点的位置和尺寸，生成 `game/src/assets/levels.ts` 内的结构化 `DifferenceLevel` 数据。坐标转换沿用现有 `geometry.ts` 的 Cocos 坐标规则。

关卡标题使用简短、规范的简体中文。标题不依赖图片内文字。

广告按钮需要使用统一视频广告标识。标识物料按 38:28 比例绘制或复用，放在按钮文字左侧，确保小尺寸按钮内不重叠、不遮挡。

## 架构

保持当前模块边界：

- `app/controller.ts` 负责流程、关卡状态、奖励广告结果、倒计时和存档更新。
- `app/save.ts` 负责兼容读取和写入存档。
- `assets/levels.ts` 与 `assets/types.ts` 负责关卡数据。
- `core/geometry.ts` 负责设计坐标、图片框和命中区域转换。
- `render/canvasRenderer.ts` 负责页面绘制、触控命中和视觉反馈。
- `platform/*` 负责浏览器和小游戏平台能力降级。

如渲染文件过长，可提取小型绘制辅助函数，但不做无关架构重写。

## 广告与降级

视频广告入口只能由玩家主动点击触发：

- 看广告获得提示。
- 看广告增加 30 秒。
- 看广告奖励翻倍。
- 看广告解锁未解锁关卡。

广告完整播放才发放奖励；玩家主动取消、跳过或关闭时不发放完整奖励。平台能力不可用、广告加载失败或接口异常时，按现有兜底策略直接发放奖励并展示明确反馈，避免阻塞核心流程。

## 存档

存档内容包括：

- 当前关卡。
- 最高解锁关卡。
- 已通关关卡。
- 金币。
- 提示次数。
- 每日奖励领取日期。
- 声音设置。

读取旧存档时字段缺失要使用默认值；异常数据不能导致游戏无法启动。关卡总数从 5 扩展到 7 后，旧存档的已解锁进度继续有效。

## 测试与验收

自动化测试：

- 关卡数据测试应覆盖 7 关，且每关 10 个差异目标。
- 坐标转换测试保留现有命中区域断言，并新增第 6 或第 7 关的资源存在性断言。
- 控制器测试覆盖顺序解锁、广告解锁、广告加时、提示、胜利后奖励翻倍和旧存档兼容。

构建验证：

- `pnpm test`
- `pnpm build`

视觉验收：

- 浏览器预览能进入首页、选关、游戏、胜利、失败和设置。
- 750 x 1334 竖屏设计下文字不重叠，按钮可点击区域明确。
- 视频广告入口均带统一广告标识。
- 核心流程在图片资源尚未加载完成时也不会崩溃。
